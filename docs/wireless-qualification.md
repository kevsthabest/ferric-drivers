# Standalone ToPIC95 / AR2413 qualification
Status: experimental, activation disabled. Never use this branch to replace a known-good boot configuration.

## Gate A: read-only baseline
- Cold boot without FERRIC.JLM, I8255X.JLM or other CardBus owners.
- Capture complete PCI config and E820/ACPI resource evidence. Confirm ALi 1644/5247 and Toshiba 1179:0617 revision 32; record both functions and interrupt routing.
- Load FRES, CARDBUS, ATH5K in that order. Run ATHDIAG on the inactive bridge and capture output.
- Expected: two bridges on the target laptop if both functions are present, no eligible powered child, probe=5, install=5, stop=0. Audit 0 means clear PCI preflight only, not firmware authorization. Slot 1 may report bus conflict because the other bridge holds a firmware placeholder.
- Run ATHSCAN; expect status 5 with no child. ATHINIT must reject disconnected install with status 5. Confirm INT 60h unchanged.
- Unload ATH5K, CARDBUS, FRES. Repeat PCI captures; no device programming should have occurred.
- Stop on unexpected results. Do not change activation constants.

## Gate B: authorize physical resources (engineering)
Compare the target's PCI BAR lengths and firmware resource reservations to the proposed socket and child apertures, including secondary/subordinate bus windows, aliases, prefetch windows and graphics. A BAR base alone is insufficient. Avoid writing all ones to live BARs. Require explicit evidence of non-overlap, a known reset/power recovery path and reversible bridge snapshots. Test one socket at a time. No DMA.

## Gate C: controlled activation (future engineering build only)
After authorization, stage decode-off/reset-asserted configuration, verify each write, map socket, power 3.3 V, identify exact 168C:001A child. No bus master. Record status at every step and verify rollback on removal, timeout and mapping failure. Check writable masks rather than treating volatile/W1C bits as restorable.

## Gate D: DMA isolation (future engineering build only)
Use a sacrificial, retained DOS allocation, verify physical contiguity and guards, initialize ring before enabling mastering. Validate engine idle, PCI child and bridge BME off, posted-write behavior and outstanding transactions. A delay/readback alone is insufficient evidence. Verify canaries, repeat shutdown and check for late writes with suitable instrumentation. On uncertainty keep memory and module resident and cold boot. Never free the block on failed stop. A test pass is not a hardware specification.

## Gate E: networking (future)
Supply a fresh external random nonce for every association. Test passive scan, known WPA2-PSK AES AP, DHCP, ARP, TCP, group rekey, repeated connect/disconnect, packet receiver release, removal and reboot recovery. Compare large and multi-file transfers against checksums. Test Ethernet vector conflict and restoration. Keep credentials out of logs and source control.

Current build can perform Gate A only. QEMU covers negative discovery and loading, not hardware activation, RF, DMA drain or WPA2 connectivity.

## Standalone DOS utilities (experimental)
ATHCONN refuses before prompting unless a stage-4 probe exists. It requires a fresh, exactly 32-byte NONCE.BIN generated by a trusted external CSPRNG per attempt; do not reuse or distribute it. SSID/channel/BSSID and passphrase are entered without echo. The request buffer is wiped, but full secret erasure is not guaranteed. On success or uncertain cleanup the utility stays resident. ATHSTOP releases the packet bridge and device lease after application receivers unregister; DOS TSR allocations remain until reboot by design. Do not treat successful stop as permission to manually free TSR memory. No live connection is possible with current gates closed.

## Captured resource reconciliation (2026-11-21 baseline)

Source: private parent repository `docs/hardware/dynabook-ss2000m-cardbus.txt` and `dynabook-ss2000m-hwscan.txt`, pre/post CBINIT captures. The proposed addresses match the legacy successful slot-0 configuration, but this is historical evidence only.

| Resource | BIOS boot | Legacy configured / proposed |
|---|---|---|
| 00:11.0 socket | BAR 0 | F7E00000–F7E00FFF |
| 00:11.1 socket | BAR 0 | F7E01000–F7E01FFF |
| Slot 0 child window | 0 | F7D00000–F7DFFFFF |
| Slot 1 child window | 0 | F7C00000–F7CFFFFF |
| Secondary/subordinate | 3/3, 4/4 | 2/2, 3/3 |
| IRQ | FF, pins 1/2 | 11 |
| Child slot 0 | none enumerated | 168C:001A, BAR F7D00000 |

The raw config dword at 18h is authoritative; the formatted bus=80/00/80 field in the old probe is inconsistent with raw bytes. Slot 1's proposed bus 3 collides with slot 0's unassigned firmware placeholder until slot 0 is reconfigured. Do not treat an unassigned BAR as authorization.

Other captured bases: F0000008 (host aperture), F7EFF000 (8255x), F7EBF000 (OHCI), FC000000 (graphics). E820 reports RAM/reserved ranges through 10000000 and ROM FFF80000–FFFFFFFF; it does not establish ownership of the unlisted high PCI MMIO space. No verified sizes of all active BARs or ACPI root bridge resource windows are available in these two captures. Firmware authorization remains false. Capture root bridge resources and actual aperture sizes independently before allowing activation.

Gate A package is diagnostic only: extract the CI artifact, copy FRES.JLM, CARDBUS.JLM, ATH5K.JLM, ATHDIAG.COM, ATHSCAN.COM, ATHINIT.COM, ATHSTOP.COM and WIFIGATE.BAT to an isolated test directory. Run WIFIGATE from a cold boot without existing hardware owners. Do not include FERRIC.JLM in this test. Preserve WIFIGATE.TXT and the screen output. The batch does not modify boot files.

## Baseline capture package

Also copy CBPROBE.COM. WIFIGATE.BAT now saves CBPRE.TXT before loading any modules, CBPOST.TXT after unloading and WIFIGATE.TXT for the intermediate status. The CBPROBE bus field now reads configuration offset 18h (not 14h) and the configuration address latch is restored after each read with interrupt flags preserved. Compare raw dwords, especially command, BAR, bus/window and bridge control. Volatile status/card-detect fields can change independently; any unexplained configuration difference blocks activation. The actual batch is exercised in QEMU with absent hardware. No physical aperture-size probing or activation is performed.
